# 安装与使用说明（USAGE）

本文档面向使用者，讲清楚**如何安装环境**和**如何用命令行运行**。
原理与公式请见 [原理与公式说明.md](原理与公式说明.md)。

---

## 1. 环境要求

- 操作系统:Linux / macOS / Windows 均可。
- Python:**≥ 3.8**。
- 第三方库:`numpy`、`scipy`(安装本工具时会自动安装,无需手动处理)。
- 可视化工具 `transforms_viz` 另需 `plotly`、`fastapi`、`uvicorn`,通过可选依赖 `[viz]` 安装(见 2.1)。

建议用一个独立的虚拟环境,避免污染系统 Python。（非必要，也可以在原有的conda环境中添加，环境配置不容易冲突）
如果需要新建环境的话，可参考1.1与1.2

### 1.1 用 conda(推荐)

```bash
conda create -n transforms_tools python=3.10 -y
conda activate transforms_tools
```

### 1.2 或用 venv

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
```

---

## 2. 安装

进入解压后的项目根目录(即包含 `pyproject.toml` 的这一层),执行:

```bash
cd transforms_tools
pip install -e .
```

- `-e` 是「可编辑安装」,便于你以后改代码即时生效;如果只想装一份固定的,去掉 `-e`:
  ```bash
  pip install .
  ```

安装成功后,系统里会多出一个命令 `transforms_tools`。验证:

```bash
transforms_tools --help
```

能看到 6 个子命令(`calibrate_rig`、`canonicalize`、`finalize`、`set_aabb`、`use_existed_trans`、`check`)即安装成功。
此外还会安装两个独立命令:`transforms_viz`(可视化,需 `[viz]`)与 `copy_first_images`(抽取代表图)。

### 2.1 安装可视化工具(可选)

如果还要用网页版 3D 位姿可视化 `transforms_viz`,安装时带上 `[viz]` 可选依赖(会额外装 `plotly`、`fastapi`、`uvicorn`):

```bash
pip install -e ".[viz]"
```

装好后系统里会多出命令 `transforms_viz`(用法见第 8 节)。

> **不想安装也能跑**:在项目根目录下用模块方式运行(需先 `pip install numpy scipy`):
> ```bash
> PYTHONPATH=scripts python -m transforms_tools --help
> ```
> 但更推荐 `pip install`,这样在任何目录都能直接用 `transforms_tools` 命令。

## 3. 输入数据约定

工具按「**目录**」批量处理。它在你给的根目录 `-i` 下,按层级 `-L` 找到一批目标目录,
每个目标目录里应包含:

- 一份 `transforms.json`(SfM 输出的相机位姿,NeRF/nerfstudio 常见格式:含 `frames`、
  每帧 `file_path` 和 4×4 `transform_matrix`,以及 `fl_x/fl_y/cx/cy/w/h` 等内参)。
- 一份**设备配置 json**(含 `CameraParametersList`,每个相机有 `CameraDisplacement` 字段)。
  用于读取每台相机的径向位移 `disp`。

### 关于 `-L`(层级,1-based)

- `-L 1`:处理 `-i` 目录**本身**。
- `-L 2`:处理 `-i` 的**直接子目录**(最常用:根下每个日期/次一个子目录)。
- `-L 3`:处理孙目录,依此类推。

### 相机编号识别

帧的 `file_path` 里需能解析出相机号,如 `..._cam01_angle0.png` → cam01;
角度 `angle0` 可选。默认参与相机为 `1..6`(可用 `--camera-ids` 修改)。

### 通用开关

所有子命令都支持 `--dry-run`:**只打印将要做什么,不写盘**。**强烈建议每一步先 dry-run 确认。**

## 4. 标准四步流程

假设数据根目录为 `/data/plant/K04`,其下每个日期一个子目录(所以用 `-L 2`)。

### 第一步:联合标定机械常数(`calibrate_rig`)

用**相机齐全**(默认 ≥6 台)的几次采集,联合解出设备机械常数 `r`、`L`,写出 `rig_calib.json`。

```bash
transforms_tools calibrate_rig \
  -i /data/plant/K04 \
  -L 2 \
  -o /data/plant/calib_K04 \
  --dry-run          # 先预览;确认后去掉

# 正式执行
transforms_tools calibrate_rig -i /data/plant/K04 -L 2 -o /data/plant/calib_K04
```

产物:`/data/plant/calib_K04/rig_calib.json`(含 `r_base_mm`、`L_mm`、每台 `R_opt_mm` 等)。

关键参数:
- `-o`:标定输出目录(必填)。
- `--min-cams`:参与标定所需的最少相机数(默认 6)。

### 第二步:对齐所有采集到统一坐标系(`canonicalize`)

用第一步的标定结果,把每次采集**缩放到真实 mm** 并**对齐到统一 canonical 坐标系**,
输出 `transforms_canonical.json`(不覆盖原文件)。有了标定,**任意相机数都能只解一个尺度**。

```bash
transforms_tools canonicalize \
  -i /data/plant/K04 \
  -L 2 \
  -rl /data/plant/calib_K04 \
  --dry-run

# 正式执行
transforms_tools canonicalize -i /data/plant/K04 -L 2 -rl /data/plant/calib_K04
```

关键参数:
- `-rl`:标定目录或 `rig_calib.json` 文件路径。**给了它就用标定复用模式**(推荐);
  不给则每个目录自行求解(需 ≥6 台相机才稳,见原理文档)。
- `--flip-z`:翻转 +Z 朝向(默认 cam06 在上、cam01 在下;方向不满意时用它反过来)。
- `--plane-cam` / `--azimuth-cam`:选哪台相机的环心落到原点、哪台的 angle0 定 +X 方位(默认都用 cam01)。

**自检**:输出里每行有 `spread=x.x%`,表示各相机反推尺度的一致性。越小越好
(经验上 <5% 正常);偏大往往意味着该次的相机顺序或 `disp` 记录有问题。

### 第三步:整理产物(`finalize`)

把 `transforms_canonical.json` 提升为正式的 `transforms.json`,其余 transforms 相关 json
(原始、备份等)归档进 `trans/` 子目录。

```bash
transforms_tools finalize -i /data/plant/K04 -L 2 --dry-run
transforms_tools finalize -i /data/plant/K04 -L 2
```

> 注意:这一步是**移动+改名**操作,务必先 `--dry-run` 看清清单再执行。

### 第四步:写训练用包围盒(`set_aabb`)【aabb的范围可根据实际情况取】

批量给每个 `transforms.json` 写入 `aabb` 与 `aabb_scale`。

```bash
transforms_tools set_aabb \
  -i /data/plant/K04 -L 2 \
  --aabb -200 -200 -200 200 200 500 \
  --aabb-scale 1 \
  --dry-run

# 正式执行
transforms_tools set_aabb -i /data/plant/K04 -L 2 \
  --aabb -200 -200 -200 200 200 500 --aabb-scale 1
```

`--aabb` 传 6 个数(min xyz + max xyz),会写成:

```json
"aabb": [[-200, -200, -200], [200, 200, 500]],
"aabb_scale": 1
```

## 5. 辅助命令:复用已有位姿(`use_existed_trans`)【可忽略，用作复制】

当某次已经算好一份 `transforms.json`,想把它复用到一批新目录,并按各目录 `images/`
里实际存在的图片过滤帧:

```bash
transforms_tools use_existed_trans \
  -i /data/plant/new_root \
  -t /data/plant/ref/transforms.json \
  -L 2 \
  --dry-run
```

- 目标目录若已有 `transforms.json`,会先加时间戳备份(内部写入 `method`、`come_from`)。
- 新写入的 `transforms.json` 会记录来源路径 `come_from`。

---

## 5.1 辅助命令:重复性诊断(`check`,只读)

判断不同次采集的位姿「能不能直接复用」。它以某次为参考,对其余每次用 Umeyama 相似变换
对齐配对相机,报告扣掉全局相似变换后的**残差**(位置 RMS、朝向角差、尺度漂移)。

```bash
transforms_tools check -i /data/plant/K04 -L 2
# 指定参考目录、并把残差换算成 mm 展示
transforms_tools check -i /data/plant/K04 -L 2 -r 20251031 --mm-per-unit 118.93
```

判读:残差占环半径亚 %、朝向零点几度 → 纯 gauge 差异,可复用;残差明显 → 真实非重复
(碰相机/对焦/轨迹漂),建议各次重算。此命令**只读,不写盘**。

## 5.2 辅助命令:抽取代表图(`copy_first_images`)

把 `<root>/<日期>/<sample>/images/` 下排序后的第 n 张图,统一复制到一个目录,
用日期前缀防重名(如 `20250928__auto_cam01_angle0.png`),常用于做预览/汇报。

```bash
copy_first_images --root /data/plant/pepper --sample K04 -n 1 -o /tmp/preview
```

- `--root`:数据集根(默认当前目录)。`--sample`:样本/相机文件夹名(默认 K04)。
- `-n`:取第几张(默认 1)。`-o`:输出目录(默认当前目录)。

## 6. 常见问题

- **`transforms_tools: command not found`**:确认已 `pip install`,且当前处于安装它的那个虚拟环境里。
- **`No frames found` / 相机识别为 0**:检查 `file_path` 是否含 `camXX` 命名;或用 `--camera-ids` 指定实际编号。
- **`标定文件不存在`**:`-rl` 指到的是标定目录或 `rig_calib.json` 文件;确认第一步已成功产出。
- **某次 `spread` 很大**:多半是这次的相机与 IP/顺序不对应,或 `disp` 记录有误,单独排查该次,别让它污染整体。
- **想反转上下方向**:`canonicalize` 加 `--flip-z`。

## 7. 一页速查

```bash
# 标定 -> 对齐 -> 整理 -> 写 aabb
transforms_tools calibrate_rig -i <根> -L 2 -o <标定目录>
transforms_tools canonicalize  -i <根> -L 2 -rl <标定目录>
transforms_tools finalize      -i <根> -L 2
transforms_tools set_aabb      -i <根> -L 2 --aabb -200 -200 -200 200 200 500 --aabb-scale 1

# 辅助:重复性诊断 / 抽代表图 / 可视化
transforms_tools check -i <根> -L 2
copy_first_images --root <数据根> --sample K04 -n 1 -o <输出目录>
transforms_viz <transforms.json ...> --port 7007
```

## 8. 可视化:网页版 3D 位姿查看器(`transforms_viz`)

一个基于 FastAPI + Plotly 的网页工具,把一份或多份 `transforms.json` 的相机位姿
渲染成可交互的 3D 场景;每个文件一组、可勾选开关,支持圆拟合、AABB 叠加等。

**前置**:先按 2.1 安装可视化依赖(`pip install -e ".[viz]"`)。

```bash
# 启动服务(可传多份 transforms.json 一起叠加对比)
transforms_viz /data/plant/K04/20251001/transforms.json \
               /data/plant/K04/20251010/transforms.json \
               --port 7007

# 也可用模块方式运行(等价)
python -m transforms_tools.visualize <transforms.json ...> --port 7007
```

参数:
- 位置参数:一个或多个 `transforms.json` 路径。
- `--host`:绑定地址,默认 `0.0.0.0`。
- `--port`:端口,默认 `7007`。

启动后浏览器打开 `http://<主机>:<端口>`。远程服务器可用 SSH 端口转发:

```bash
ssh -L 7007:localhost:7007 <user>@<remote>
# 然后本地打开 http://localhost:7007
```
